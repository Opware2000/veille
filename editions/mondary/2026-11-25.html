En bref

Cinq billets publiés hier par Clément Mondary, tous sur des outils de développement. Trois agents de code en font les frais (Orchestrator, MonoCode, Rune), le quatrième (MonoCode) est directement exploitable pour enseigner l'informatique au lycée. Un sampler multimédia ne passe pas le tri.

Intelligence artificielle, agents et modèles locaux

ORCHESTRATOR — application de bureau gratuite et open source qui coordonne plusieurs agents de code en parallèle. Chaque tâche se voit attribuer son agent, sa branche Git et son worktree isolé, et la pull request associée est suivie jusqu'au merge. L'outil prend en charge une trentaine d'agents (Claude Code, Codex, Cursor, OpenCode, Aider, GitHub Copilot, Gemini CLI…) ; on choisit l'agent et le modèle par tâche. Il utilise les binaires installés localement avec vos abonnements existants et ne revend aucun token. Un tableau de bord classe automatiquement les sessions (Working, Needs you, In review, Ready to merge) à partir de l'activité réelle des agents, de l'état de la CI et des revues. Un mécanisme de boucle de retour renvoie les conflits, les échecs de check ou les commentaires de revue vers le worker responsable. Un agent reviewer peut lire chaque PR avant validation. Le cloud est optionnel (Starter à 20 $ / mois), les apps iPhone, iPad et Android sont gratuites. github.com/OrchestratorInc/agent-orchestrator — article : mondary.design

MONOCODE — application de bureau qui rassemble Claude Code, Codex, Cursor, OpenCode et onze autres agents en ligne de commande dans un seul environnement. Sessions en onglets, panneaux côte à côte, éditeur intégré et barre Changes pour stager, commiter et pousser sans quitter l'application. Worktree Git par tâche parallèle pour éviter les collisions. MonoCode s'appuie sur les CLI déjà installés et les connexions existantes — il ne revend aucun token. Une couche /operator permet à un agent pilote d'ouvrir d'autres sessions et de gérer des worktrees, avec des « Monos » expérimentaux qui traversent les projets et gardent une mémoire. Le mode distant fonctionne via SSH sur Windows, Linux et macOS : les sessions continuent même après fermeture du desktop. Disponible sur macOS Apple Silicon et Intel, Windows x64, Linux x86_64 (.deb, .rpm, AppImage), avec un compagnon iPhone passager. usemono.dev — article : mondary.design

RUNE — framework d'interface en Rust rendu par le GPU, avec son propre moteur de rendu, de texte, de mise en page et d'animations à ressorts. Cible macOS, Windows, Linux et le web, sans WebView ni pont JavaScript. Ce qui distingue Rune ici, c'est son traitement des agents de code comme de vrais utilisateurs d'interface : une application peut tourner sans fenêtre ouverte, rendre une capture PNG, exposer son arbre d'éléments en JSON et rejouer un script d'entrées horodatées (clics, glissements, frappe, molette). Un agent construit un écran, le regarde, clique dedans et vérifie le résultat sans capture approximative. La bibliothèque rune-kit fournit boutons, switches, menus, listes et champs riches lisant des jetons sémantiques depuis un thème décrit en JSON. Licence et prix non précisés dans le billet source. github.com/anomalyco/rune — article : mondary.design

Terminal, fichiers, sauvegarde, auto-hébergement et réseau

WHISKER — framework UI Rust-first en pré-alpha qui maintient une seule base Rust (état, mise en page, rendu) et la projette sur iOS, Android, web et desktop via des hosters natifs (UIKit, vues Android, DOM, wgpu). Pas de VM Dart, pas de moteur JavaScript, pas de DOM virtuel : les components s'exécutent une fois et seuls les attributs liés aux signals changés sont mis à jour. Hot reload sous la seconde sur le chemin Tier 1 (code modifié uniquement). DSL inspiré de JSX typé par Rust, hot plugin par modules Kotlin et Swift. Pré-alpha ouvert mais API encore mobile. whisker.rs — article : mondary.design

Volume

Cinq billets examinés, trois retenus, deux écartés (STITCHES : instrument musical sans intérêt pédagogique, WHISKER : framework Rust pré-alpha trop tôt pour l'enseignement lycée).
