Veille r/opencode — mercredi 25 novembre 2026

En bref

OpenCode v2.4.1 corrige un bug de compaction et ajoute la prise en charge des modèles configurés uniquement dans le fichier .env, tandis que le navigateur intégré (v2.4.0) importe historiques et extensions des navigateurs classiques. Du côté Anthropic, Claude Ship (bêta) automatise la revue et l'approbation de PR, et Skills over MCP (bêta publique) permet aux serveurs de livrer des compétences structurées alongside leurs outils. La souscription Claude Code s'utilise désormais dans opencode Go.

Versions et fonctionnalités

OpenCode v2.4.1 — corrections et nouveautés (23 nov.)

Cette version résout un problème critique sur macOS 12 : les messages assistant se sauvegardaient à nouveau après une régression SQLite, et corrige deux bogues liés à la compaction — l'une faisait retenir trop d'historique récent par rapport au paramètre keep.tokens, l'autre générait un coût de cache excessif après compaction dans les sessions longues. Les fournisseurs définis uniquement dans la configuration (Ollama, etc.) apparaissent désormais dans /models sans étape de connexion. Le changement de comportement expérimental experimental.model_speeds expose les niveaux de service comme des vitesses mémorisées plutôt que comme des entrées séparées du sélecteur de modèle. Les automations Extensions bénéficient désormais de ctx.experimental.automation.{create, list, delete} pour piloter scripts et commandes horaires directement depuis un plugin. Source : changelog.opencode.ai.

Navigateur desktop intégré — OpenCode v2.4.0 (23 nov.)

Deux jours avant la v2.4.1, OpenCode a livré son navigateur intégré : il importe identifiants connectés, historique de navigation et extensions depuis Chrome, Edge, Firefox ou Safari. Tout reste dans un profil persistant unique ; les liens ouverts depuis le chat sont déjà authentifiés, les onglets survivent aux redémarrages et l'agent peut lire et piloter les mêmes pages sans basculer entre applications. Des automations sont également disponibles — lancer un prompt, un script ou une commande shell à intervalle régulier ou sur déclencheur (démarrage, activation de session). Source : opencode.ai/changelog.

Navigateur open-source GPUI se dote de son propre dépôt

Le moteur GPU-accelerated UI utilisé par Zed passe dans un dépôt indépendant (github.com/zed-industries/gpui). La communauté Hacker News y consacre 81 points et 16 commentaires. GPUI sous-tend l'écosystème des agents TUI modernes — pertinent pour ceux qui construisent au-dessus ou souhaitent comprendre les performances du frontend opencode. Source : Hacker News.

Modèles, fournisseurs, limites et coûts

La souscription Claude Code fonctionne dans opencode Go

Plusieurs discussions dans la communauté r/opencode confirment qu'il est possible d'utiliser sa souscription Claude Code (Pro ou Plus) comme fournisseur dans opencode Go. La page officielle docs.opencode.ai/console/go/ décrit la procédure : configurer un « Cross Harness Provider » avec les identifiants existants. Les utilisateurs signalent toutefois des comportements variables — consommation de quota mal comprise, problèmes d'accès à certains modèles, et erreurs aléatoires sur DeepSeek Flash 4.1. Un commentaire soulève la question de savoir si cette intégration pourrait être supprimée à terme. L'accord sous-jacent est valable jusqu'au 30 novembre 2026. Cette information mérite vérification directe auprès d'opencode avant tout investissement.

Muse Ember (anciennement Crouton Alpha) — maintenant disponible sur opencode

Le modèle léger de Meta Superintelligence Labs a été ajouté à opencode le 9 novembre. Tarif indiqué : entrée à 0,10 $/M tokens, sortie à 0,50 $/M, inférence non chiffrée. La communauté le compare souvent à DeepSeek Flash 4.1 pour les tâches locales et légères, avec des résultats mitigés sur la cohérence. Le volume tokenisé via opencode atteint 2,2T tokens cumulés (source : opencode.ai/data/meta/muse-ember-1-0). Certains utilisateurs constatent que les limites gratuites semblent fluctuer selon les heures de pointe.

OpenRouter : Google dépasse OpenAI en dépenses cette semaine

Les utilisateurs OpenRouter ont dépensé plus ce mois-ci sur les modèles Google que sur ceux d'OpenAI, selon un tweet de @openrouter publié récemment. Le sujet suscite moins de discussion que d'habitude (12 points, 2 commentaires), mais l'annonce reflète un décalage notable dans les préférences des développeurs travaillant avec des agents. Source : X / Twitter.

Paradoxe de Jevons dans l'IA : des jetons moins chers n'amortiront pas le CapEx

Un article analysé sur Hacker News (31 points) soutient que la baisse du prix des jetons LLm entraîne une augmentation de la demande et donc des investissements infrastructurels, annulant les économies attendues. Bien que général, cet argument concerne directement toute personne qui utilise opencode avec plusieurs fournisseurs à faible coût et observe une hausse des besoins compute. Source : philippdubach.com.

MPC tool lists : combien de contexte coûtent 100 serveurs publics avant votre prompt

Une analyse mesure l'impact des listes d'outils exposées par les 100 serveurs MCP les plus populaires sur la taille totale du prompt envoyé à chaque requête. Résultat : certaines configurations ajoutent des milliers de tokens inutilisés avant même que l'utilisateur n'ait posé sa question, ce qui alourdit les coûts et ralentit les premières réponses. Source : github.com/Suncly-Tech/mcp-reliability-index.

Plugins, intégrations et outils annexes

Claude Ship (bêta publique)

Anthropic lance Claude Ship, un ensemble de trois agents pour automatiser le cycle post-PR : Code Review (déjà GA) effectue une revue approfondie via multiples angles et catégorise les findings ; PR Steward maintient vert un PR en intervenant sur les échecs CI, conflits de merge et feedback de review ; Claude Approvals applique une politique d'approbation écrite comme fichier dans le dépôt, fonctionnant comme un CODEOWNERS intelligent. Éligible Enterprise : au moins 10 000 $ de crédits Claude Ship dans les 30 jours premiers, à réclamer avant le 15 janvier 2027. Sur l'équipe interne Claude Code, les PR fusionnés ont plus que doublé entre juin et septembre, avec un revert tombé de plus de 40 %. Source : claude.com/resources/articles/introducing-claude-ship.

Skills over MCP (bêta publique)

Les serveurs MCP peuvent désormais livrer des « skills » alongside leurs outils. Claude charge un skill uniquement quand nécessaire, gardant l'utilisation du contexte minimale. Déjà en place chez Shopify (design boutique), HubSpot (onboarding), Atlassian (contexte organisationnel), Carta (actions equity documentaires). Disponible par défaut pour les plans Pro, Max et Ultra de Claude, accessible aux plans Team une fois activé par un admin. S'intègre à Claude Code et Claude.ai. Source : claude.com/resources/articles/skills-over-mcp-tasks-and-more.

Genesis Map — visualiser les changements d'un agent dans le codebase

Genesis Agent Infra — CLI locale et skill pour Claude Code, Codex et autres agents — transforme votre codebase en carte de flux métier et montre quels changements de l'agent ne sont pas testés ou risqués. Python, TypeScript et langages courants supportés. Licence Apache-2.0, 70 étoiles GitHub, dernière mise à jour le 25 novembre 2026. Source : github.com/GenesisAgentInfra/genesis.

Songe — entraîner un modèle local avec le compute idle

sous-labs/songe — moteur d'entraînement pour modèles locaux utilisant le compute inutilisé. Langage Python, licence Apache-2.0, 664 étoiles GitHub, dernière activity hier soir. Idéal pour ceux qui disposent de GPU inactifs et veulent affiner un modèle pour leurs usages spécifiques avec opencode. Source : github.com/sous-labs/songe.

Wakeshift — événements MCP interoperables pour Claude Code, Codex et plus

wakeshift/server — rend n'importe quel serveur MCP capable de servir des événements interoperables via le protocole MCP Events ou des ponts spécifiques à chaque harness. Permet aux serveurs MCP de pousser des événements vers des clients qui ne supportent pas nativement MCP Events aujourd'hui, incluant Claude Code, Codex et Cursor. Spécification MCP Events approuvée et fusionnée il y a cinq jours seulement. Source : github.com/wakeshift/server.

Versine — transfert d'argent parlant ou textant à votre IA

Versine (YC F26) — un serveur MCP placé devant un portefeuille avec solde, permettant à votre agent d'envoyer et de demander de l'argent en discutant ou textant. Équivalent Venemo pour agents IA. Portée par des ingénieurs ayant travaillé chez Stripe, Databricks et Amazon. Sujet très actif sur HN (27 points, 8 commentaires). Source : news.ycombinator.com/item?id=50634426.

Mcpseal — évaluer la sécurité d'un serveur MCP avant installation

@hashshabbir/mcp-pack — package npm visant à noter/score une sécurité d'un serveur MCP donné avant de l'installer, en vérifiant permissions, accès réseau et données exposées. Nouveau, peu de retours à ce jour (1 point sur HN). Source : npmjs.com/package/@hashshabbir/mcp-pack.

PlumCalc — 33 calculateurs côté client avec serveur MCP public

plumcalc.com — collection de 33 calculateurs utilisés en frontend, accessibles via un serveur MCP public pour injection dans des flux d'agents. Serveur léger, aucun backend requis. Source : plumcalc.com.

Aisma — éditer des vidéos à partir d'un brief texte, via REST API ou MCP

aisma.ai — comprend des demandes simples de modification vidéo, explique au modèle de génération ce qu'il faut changer exactement, et ignore les parties où rien ne change, réduisant ainsi les coûts. Fonctionne dans tous les navigateurs, apps iOS et Android natives, ainsi que via API et connexion MCP. Source : aisma.ai/developers.

Méthodes et retours d'expérience

Utiliser sa souscription Claude Code comme fournisseur dans opencode Go

La discussion principale (reddit.com/r/opencode/comments/1xjujne) détaille la configuration : activer le mode « cross-harness » dans opencode, pointer vers le endpoint Claude Code, fournir les credentials. Plusieurs rapports convergent — ça marche, mais le quota peut être partagé différemment de ce qui est annoncé, et certains modèles payants Claude Code ne sont pas toujours disponibles dans le selector opencode. Vérifier la disponibilité exacte avec ses propres identifiants avant de compter dessus pour un usage régulier.

Orchestrer des sous-agents avec état partagé

Un utilisateur explique comment gérer l'état entre sessions de sous-agents en leur fournissant un fichier de contexte persistant (state.json) lu à chaque invocation. Technique simple mais efficace : écrire les résultats intermédiaires dans un répertoire commun, chaque sous-agent lit ce qui a été produit avant lui, et écrit ses conclusions. Permet un pipeline séquentiel sans boucle infinie. Source : discussion communautaire r/opencode.
