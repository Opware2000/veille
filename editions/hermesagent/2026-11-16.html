En bref

  • Une seule annonce concrète dans le journal du subreddit : le canari du 15 novembre de Hermes Agent, qui publie des binaires de bureau pour macOS et Windows et verse une nouvelle fournée de greffons au catalogue.
  • Les sources complémentaires apportent deux mises à jour de l'écosystème Datasette, dont la prise en charge des points d'accès compatibles OpenAI — de quoi faire tourner Datasette Agent sur un modèle local.

Nouveautés et mises à jour

Hermes Agent — canari v0.23.1+canary.20261115T064406Z (15 novembre). La publication du jour met en ligne les applications de bureau Hermes pour macOS Apple Silicon (DMG) et Windows en 64 bits comme en ARM (MSIX), avec les contrôles automatiques d'installation et de conversation réussis sur ces trois formats ; les paquets Linux sont désactivés. C'est une préversion : à réserver aux essais, la production restant sur la 0.23.1 stable. Un détail de cette dernière mérite d'être connu : la 0.23.1 (9 novembre) a corrigé un défaut qui rendait l'installation de greffons silencieusement inopérante — le catalogue publié dépassait la taille que les clients acceptaient, chaque hermes plugins install retombait sur le catalogue embarqué dans la version installée, sans message d'erreur ; le plafond est passé de 2 à 16 Mio. Si une installation de greffon a échoué sans explication depuis le 9 novembre, la mise à jour est la réponse. Dépôt NousResearch/hermes-agent, licence MIT, 263 637 étoiles, dernière poussée le 15 novembre à 23 h 46 UTC.
https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.1%2Bcanary.20261115T064406Z

llama.cpp passe en version 1.0.0. Le moteur d'inférence local en C/C++ franchit le cap de la version 1, annoncé sur le blog de l'organisation ggml ; c'est la brique qui fait tourner la plupart des modèles locaux sur un ordinateur ordinaire, et donc un préalable à tout agent sans facture d'API. Repère pratique : les étiquettes du dépôt GitHub ne portent pas de version lisible (ce sont des numéros de construction, b12427 le 15 novembre), la version se lit sur le blog. Licence MIT, 135 202 étoiles, dernière poussée le 15 novembre à 23 h 47 UTC.
https://huggingface.co/blog/ggml-org/llama-cpp-v1

datasette-vega 0.7 (14 novembre). Le plus ancien greffon de Datasette encore vivant — il dessine des graphiques Vega-Lite sur une table ou une requête — n'avait pas été publié depuis juillet 2018. Cette version le remet en compatibilité avec les versions de développement récentes et avec Datasette Lite, qui sait désormais exécuter des greffons JavaScript : la démonstration du README s'ouvre donc directement dans le navigateur, sans installation. Dépôt simonw/datasette-vega, licence Apache 2.0, 65 étoiles, dernière poussée le 14 novembre.
https://github.com/simonw/datasette-vega/releases/tag/0.7

Extensions et greffons

datasette-llm 0.1a11 (14 novembre) — brancher un modèle local. Ce greffon intermédiaire sert à configurer les modèles que les autres greffons Datasette utilisent. La version 0.1a11 accepte les points d'accès compatibles avec le protocole d'OpenAI, ce qui permet de faire tourner Datasette Agent sur un modèle servi par LM Studio, Ollama ou llama.cpp : une adresse locale et un nom de modèle suffisent, sans clé ni abonnement. Dépôt datasette/datasette-llm, licence Apache 2.0, 20 étoiles, dernière poussée le 14 novembre — attention, l'ancien dépôt simonw/datasette-llm est archivé, c'est bien le dépôt de l'organisation datasette qu'il faut suivre.
https://github.com/datasette/datasette-llm/releases/tag/0.1a11

Catalogue de greffons Hermes — fournée du canari du 15 novembre. La publication ajoute une série d'entrées au catalogue. Les notes de version en donnent quelques-unes avec leur objet : video-xray (atelier d'analyse vidéo), AutoRAG (recherche locale dans les documents et les archives), luminary (fournisseur de mémoire auto-hébergé), hermes-janus (moteur d'état temporel), permission-tiers (paliers de permissions), dosbox-mcp, QMD Workspaces et Asset Curator. D'autres n'y figurent que par leur nom — hermes-eye-memory, neuralwatt-provider, munito-provider, datacircle, inkly, hermes-slots, plansift, locksift, CrowdCode, worktable, et les mises à jour ascii-worlds 1.4.0, progression 1.2.0 (signaler une conversation ou un sous-agent en attente d'une réponse), stoa 0.18.0, printwatch 0.4.0 — que je ne décris pas ici faute d'information dans la note de version ; à regarder au cas par cas dans le catalogue.

Une piste non vérifiée par moi

Un fil du subreddit demandait quels espaces de travail savent orchestrer plusieurs agents ; l'auteur y citait trois dépôts. Je les ai vérifiés à l'API GitHub mais je ne les ai pas essayés, donc je les signale sans les recommander :

  • OrchestratorInc/agent-orchestrator — Apache 2.0, 14 736 étoiles, dernière poussée le 15 novembre ; décrit comme un outil pour « planifier, lancer et superviser des flottes d'agents, de la tâche à la requête fusionnée », avec des applications de bureau (macOS, Windows, Linux) et mobiles. https://github.com/OrchestratorInc/agent-orchestrator
  • stablyai/orca — MIT, 125 741 étoiles, dernière poussée le 15 novembre ; exécute une flotte d'agents de code (Claude Code, Codex) avec des abonnements personnels, sur poste, mobile et serveur distant. https://github.com/stablyai/orca
  • omnigent-ai/omnigent — Apache 2.0, 11 387 étoiles, dernière poussée le 15 novembre ; cadre d'agents « méta-harnais » qui orchestre Claude Code, Codex, Cursor, Pi et des agents maison. https://github.com/omnigent-ai/omnigent
